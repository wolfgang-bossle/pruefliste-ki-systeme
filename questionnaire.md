Fragen, die in einer Abnahme gestellt werden — von Revision, Auftraggeber, Datenschutz. Die rechte Spalte ist die Nachfrage, wenn die Antwort ausweicht.

Aufgenommen wurde nur, was einen Nachweis erzeugt: ein Dokument, ein Protokoll, einen Testlauf, eine Entscheidung mit Person und Datum.

> **Zweck und Vorbehalt**
>
> Der Fragebogen wurde erstellt, um bei der Abnahme eines KI-Systems eine unverbindliche Hilfestellung zu geben: Er sammelt Fragen und benennt, was als Antwort nicht genügt. Wer ihn einsetzt, entscheidet selbst, welche Fragen im konkreten Fall zu stellen sind und ob eine Antwort ausreicht.
>
> Es wird keinerlei Prüfung, prüferische Durchsicht, Rechts- oder Steuerberatung erbracht. Es wird keinerlei Zusicherung oder Gewähr für Vollständigkeit oder Richtigkeit übernommen und kein Urteil über ein System, einen Anbieter oder eine Rechtslage abgegeben.
>
> Die Fragen sind aus den veröffentlichten Leitfäden der vier Claude-Zertifizierungen abgeleitet. Anthropic hat daran nicht mitgewirkt; Inhalte der Zertifizierungsprüfungen selbst gibt das Dokument nicht wieder.

# Review questions for AI systems covering Selection · Build · Operation · Evidence

*derived from the four Claude certifications*

Wolfgang Bossle, CPA · Claude Certified Architect  
https://www.linkedin.com/in/wolfgang-bossle/

The questions asked at sign-off — by internal audit, by the sponsor, by data protection. The right-hand column is the follow-up when the answer evades.

Only what produces evidence was kept: a document, a log, a test run, a decision with a person and a date.

> **Purpose and disclaimer**
>
> This questionnaire was prepared to offer non-binding assistance at the sign off of an AI system: it collects the questions and names what does not count as an answer. Anyone using it decides which questions apply in the case at hand and whether an answer suffices.
>
> No audit, no review, no legal or tax advice is provided. No assurance or warranty as to completeness or accuracy is given, and no conclusion is reached about any system, any vendor, or any legal position.
>
> The questions are derived from the published guides of the four Claude certifications. Anthropic took no part in this document; no certification exam content is reproduced.

## Selection — Before anything was built

| # | | What does not count |
|---:|---|---|
| 1 | Which document states what the system must deliver — and who on the business side signed it off? | A ticket or a slide deck. A requirement written down after the build. |
| 2 | Which use cases are approved, and which class of data is permitted for each? | A list without its counterpart — approved cases but no explicitly excluded ones. “No sensitive data” without a definition of what counts as sensitive. |
| 3 | Where is it recorded who approved which model for this use case, and on what date? | The model name alone. “We use the best one.” A decision without a decision-maker. |
| 4 | Was it decided whether the system follows a fixed workflow or acts on its own (agentic) — and where is the reasoning? | “It turned out that way.” An architecture diagram without the rejected alternative. |
| 5 | Which failure modes were named before the build, and what damage does each cause? | “Hallucinations” as the only entry. A risk list without an impact figure. |
| 6 | Where does the system run, who operates it, and who is liable when it fails? | A vendor name without a contract. “In the cloud.” |

## Build — How the system is put together

| # | | What does not count |
|---:|---|---|
| 7 | Which tools does the system have, which of them write or execute, and which run without confirmation? | A tool list without a reason per entry. “Whatever the framework ships with.” |
| 8 | Under which identity does the system act, and where do that identity's permissions come from? | A technical account whose permissions no one can trace. The permissions of whoever built it. |
| 9 | Which guardrails and stopping points are built in, and which test case shows they hold? | An instruction in the prompt as the only barrier. A guardrail that has never fired. |
| 10 | Which data sources and services are connected, with what scope of access each, and who operates them? | An inventory listing only in-house systems. Read access “to the drive”. |
| 11 | Which data leaves the organization, to whom, and by which route? | “The data stays with us” without a diagram. A diagram without the processing location. |
| 12 | How is the system protected against instructions smuggled in through processed content (prompt injection) — and which test case proves it? | “The model catches that.” An instruction to ignore instructions. |
| 13 | Which rules validate the output before it is processed further, and what happens on a violation? | A check that only logs. Format validation without content validation. |
| 14 | Where is the configuration held under version control — rule files, settings, pinned model version, prompt versions? | Prompts in chat histories. A configuration without history. |
| 15 | Who reviewed the machine-generated code, and where is that on record? | “We tested it.” A review by the same system that produced the code. |

## Operation — What the running system produces

| # | | What does not count |
|---:|---|---|
| 16 | What is logged, what persists between sessions, where does it live, for how long, and who can read it? | Logs that only appear on error. A retention rule without a deletion date. |
| 17 | Which faulty outputs have occurred so far, and how was it established whether the integration or the model caused them? | “None so far.” A recollection without a record. |
| 18 | Which model version is the system pinned to, and what happens when the vendor deprecates it? | “We’ll take the new one then.” A pin without a check that the successor answers the same. |
| 19 | Where are the access keys held, who has access, and when were they last rotated? | A key in a configuration file. “Only the developer knows it.” |
| 20 | How is the move from test to production governed, and where is the approval recorded? | Test and production are the same. Approval by word of mouth. |

## Evidence — What is put in front of a third party

| # | | What does not count |
|---:|---|---|
| 21 | Against which test dataset is the system evaluated, which threshold applies, and how did the last run go? | Examples that came up during the build. A test without a threshold — it cannot fail. |
| 22 | For which outputs does a human sign off, and where are the signed cases? | “Someone always looks it over.” A rule without cases. |
| 23 | For which figure in the output can the source it came from be named, and in which version? | A list of sources at the end with no link to the individual statement. A source without an edition or version. |
| 24 | Which documents are on file — data processing agreement, record of processing activities, processing region? | A pointer to the vendor’s privacy policy. An assurance from the sales call. |
| 25 | Which AI policy has been in force since when and for whom — and which limits of the system have been communicated to users? | A draft. A policy the users have never seen. |
| 26 | Which alternative was rejected, by whom, and on what grounds? | Only the decision taken. A rationale without a person. |
